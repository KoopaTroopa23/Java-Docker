Docker & Container Basics — Study Notes
Developers vs. Operations — The Old Problem


================
|  SECTION 1:  |
================


In traditional software delivery, developers wrote the code and a separate operations team handled deployment. To get an app running, operations had to manually gather and configure multiple files — dependencies, environment settings, server configs — and make them all work together on the target machine. This was slow, error-prone, and highly dependent on the specific environment it was deployed to. An app that worked fine on a developer's laptop could easily break on the server because the environments weren't identical.

How Docker Solved This

Docker packages an application together with everything it needs to run — code, dependencies, runtime, system libraries — into one self-contained unit. That unit behaves the same way no matter where it runs.

The process:

Developers write a Dockerfile — a plain text file with step-by-step instructions for how to build the application into a container (what base system to start from, what to copy in, how to run it).
The Dockerfile is used to build a Docker Image — a packaged, ready-to-run snapshot of the application and everything it needs.
The Image is used to run the application as a container — a live, running instance of that image.

Because the image contains everything the app needs, it runs the same way on a developer's laptop, a test server, or in production. That consistency is what closed the gap between developers and operations — and that convergence is a big part of what gave rise to DevOps: developers and operations working from the same reproducible artifact instead of two disconnected processes.

Docker Engine is the software that actually builds images and runs containers. It's available on Linux, Mac, Windows, and in the cloud — the same Dockerfile produces the same result regardless of platform.

-------------------------------
Essential Docker Commands     |
-------------------------------

Command	What it does

--- CONTAINER MANAGEMENT ---
docker ps                   # List all currently running containers
docker ps -a                # List all containers (including stopped ones)
docker run <image_name>     # Create and start a container from an image
docker stop <container_id>  # Gracefully stop a running container
docker rm <container_id>    # Remove a stopped container

--- IMAGE MANAGEMENT ---
docker images               # List all locally available images
docker history <image_name> # Show the history and layers of an image
docker rmi <image_name>     # Remove a local image

--- MULTI-CONTAINER (COMPOSE) ---
docker compose up --build   # Build images and start the project containers

--- COMMON RUN FLAGS & ARGUMENTS ---
-p <host_port>:<container_port>
    Makes your app reachable from your computer.
    Example: -p 9090:8080 lets you open the app at http://localhost:9090

-i
    Keeps the container running so it can accept input.
    (You usually use this together with -t.)

-t
    Makes the container act like a normal terminal window.

-it
    Opens an interactive terminal inside the container.
    You will see logs on your screen.
    You can type commands inside the container.

--name <container_name>
    Gives your container a custom name instead of a random one.

--mount type=bind,source=<host_path>,target=<container_path>
    Lets the container use a folder or file from your computer.
    Example: share logs, configs, or code with the container.

================================================================================
Notes:
* Replace placeholders like <image_name> or <container_id> with your actual data.
* Run 'docker --help' in your terminal for a full list of commands.

Building and Running Your Java App in Docker        |
-----------------------------------------------------


Create a Dockerfile in the root of your project.

1)  Build your project
    ./gradlew clean build --refresh-dependencies
1)   Build your JAR file using Gradle:
   ./gradlew bootJar
2)   Build the Docker image from your Dockerfile, tagging it java-docker:
   docker build -t java_docker .
3)   Run the container, mapping port 9090 on your machine to port 8080 inside the container:  **  Once you execute the docker run command, this makes an image a container.
   docker run -p 9090:8080 java-docker
Visit http://localhost:8080 — take you to Jenkins
Visit http://localhost:9090 — this is the mapped port from Step 4, taking you to your Java/Docker app's endpoint through the port mapping you set up.
4)  To Run Docker in the background   docker run -d (name)     OR   docker run -d -p 9090:8080 java-docker

TROUBLESHOOTING Dockerfile   |
------------------------------

docker run -it <image>
    Runs the container and shows everything happening inside.
    You will see logs on your screen.
    You can type commands inside the container.
    Useful when your container starts and immediately exits.

docker run -it <image> bash
    Opens a shell inside the container.
    Lets you check files, folders, environment variables, and paths.
    Perfect for debugging broken Dockerfiles.

BUILDKIT  / buildx                      |
-----------------------------------------


BuildKit is Docker’s advanced build engine, and `docker buildx` enables all of its modern features:

1. **Cache mounts**
   Use `RUN --mount=type=cache` to speed up builds by caching package downloads and build artifacts.

2. **Secret mounts**
   Use `RUN --mou
   nt=type=secret,id=mykey` to securely access secrets (API keys, tokens) during the build without baking them into the image.

3. **Multi‑platform builds**
   Build images for multiple operating systems and architectures:
   docker buildx build --platform linux/amd64,linux/arm64 -t java-docker --push .

4. **Parallel build stages**
   Build multiple stages (e.g., frontend + backend) at the same time:
   docker buildx build -t java-docker .
